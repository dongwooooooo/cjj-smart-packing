## 실행 시간 (ms, Execution Time)

| 쿼리 | 주기 | RDS 20,317행 | 로컬 20,317행 | 로컬 1,051,454행 |
| --- | --- | ---: | ---: | ---: |
| 집계기 ADVANCE | 5초 뒤(fixedDelay) | 54.1 | 27.2 | 1,425.1 |
| 집계기 LAG | 같은 호출 | 5.3 | 2.9 | 55.6 |
| 대조기 MISMATCHES | 60초 뒤(fixedDelay) | 11.4 | 5.7 | 281.7 |
| 대조기 음수 잔고 | 같은 호출 | 0.2 | 0.9 | 28.2 |

ADVANCE 의 두 서브쿼리가 원장 크기에 비례해 기본 키를 훑는다. 정착 경계를 찾는 `MIN(y.id)`(created_at ≥ 지금−60초)와 정착한 마지막 id 를 찾는 `MAX(t.id)` 둘 다 `inventory_tx_pkey` 를 id 범위(`id > last_tx_id`)로 걸으며 product_id·created_at 을 필터로 버린다. 로컬 1,051,454행에서 두 서브쿼리 모두 루프당 평균 약 55.7만 행을 버렸다(17루프). 원장이 없는 상품 9개는 `last_tx_id` 가 0 이라 원장 전체를 훑는다.

## RDS CPU 추정

집계기는 `@Scheduled(fixedDelay = 5000)` 이라 주기는 5초 + 실행 시간이다. UPDATE 한 문장은 코어 하나에서 돈다.

- RDS 실행 시간 = 로컬 × 2(20,317행에서 54.1 / 27.2 = 1.99 배를 그대로 외삽, 105만 행에서는 캐시 조건이 달라 미확인)
- 원장 1,051,454행: 1,425 × 2 ≈ 2.85초 → 2.85 / (5 + 2.85) = 코어 1개의 36% = 2 vCPU 의 약 18%
- 원장 약 90만 행(22:50 측정, 23:05~23:35 부하 없는 구간): 1,425 × 0.86 × 2 ≈ 2.44초 → 2.44 / 7.44 = 코어 1개의 33% = 2 vCPU 의 약 16%

관측: 부하 없는 구간의 RDS CPU 최솟값(5분 버킷 안 1분 최솟값)이 원장 약 90만 행일 때 29%, 원복 뒤 6%. 차이 23%p 중 ADVANCE 추정이 16~18%p, 나머지 5~7%p 는 미확인(LAG·대조기·autovacuum 후보).

## 완료 1건당 DB 버퍼 접근

`buffers-per-complete.json`. 계산식: `sum(rate(pg_stat_database_blks_hit{datname="app"}[판독 구간])) / 완료/s`. 분자는 DB 전체 접근량이라 집계기·대조기 스캔도 들어 있다(요청 경로만의 값이 아니다).

| 시점 | 조건 | 완료/s | 블록/s | 블록/완료 |
| --- | --- | ---: | ---: | ---: |
| 09-25 20:40 | sat 풀 10 r1(원장 약 47만 행 이전) | 113.4 | 707,626 | 6,241 |
| 09-25 22:45 | verify-1s 풀 10/1000 r2 | 84.1 | 989,329 | 11,758 |
| 09-25 23:59 | verify 풀 10/3000 r2(약 105만 행) | 55.1 | 878,268 | 15,925 |
| 09-26 00:22 | verify-controlled 풀 10 r1(원장 20,317행) | 125.4 | 230,956 | 1,842 |
| 09-26 01:01 | sat-fixed 풀 10 r1(원장 20,317행) | 125.2 | 215,144 | 1,719 |

원장을 되돌리면 완료당 블록이 약 1.8천으로 내려간다. 표류 구간에서 늘어난 몫은 요청이 아니라 집계기 스캔이 차지한 것으로 본다.

## 조건당 원장 증가 행 수

계산식: 조건 하나(워밍업 포함 k6 전체 실행)의 포장 완료 건수 × 배송단위당 품목 행 수 2.539(실험 묶음 평균, `shipment_item` 기준, 포장 완료가 품목마다 원장 한 행). 완료 건수는 각 조건 `summary.json` 의 `complete_duration.count`.

- 포화 풀 10·20(원복 전): 21,155~24,484건 × 2.539 ≈ 5.4만~6.2만 행
- 포화 풀 2·5: 5,309~14,647건 × 2.539 ≈ 1.3만~3.7만 행
- 피크 부하(1분 1건): 400~1,200건 × 2.539 ≈ 0.1만~0.3만 행
