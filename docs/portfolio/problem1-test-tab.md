## 박스 추천 대량 주문 테스트

**테스트 목적**

- 주문 수가 늘어도 박스 계산 시간이 유지되는지, 추천한 박스가 모두 택배 접수 한도를 지키는지 확인했습니다.

**테스트 환경**

| 구성 | 사양 |
| :-: | :-: |
| 실행 환경 | Apple M2 Pro 10코어, JDK 25, 단일 스레드 |
| 측정 대상 | 박스 계산 로직 (DB, API 호출 제외) |
| 상품 | 500종 (시연 상품 11종의 치수를 ±20% 변형, 무게는 부피에 비례) |
| 박스 | 6종, 택배 접수 한도 20kg / 세 변 합 160cm / 최장변 100cm |

**테스트 시나리오**

- 주문 1건은 상품 1종에서 10종, 종류마다 1개에서 5개로 구성했습니다(주문당 평균 16.5개, 최대 45개).
- 주문을 100건, 1,000건, 5,000건으로 늘리며 계산 시간과 추천 결과를 확인했습니다.

**테스트 과정**

1. **계산 시간**

- 5,000건을 21.0초에 계산했고, 주문당 p95는 13.8ms였습니다.
- 주문 수를 50배로 늘려도 주문당 평균 시간은 3.6ms에서 4.2ms로 1.16배에 그쳤습니다.

2. **무게 판정 전후 비교**

- 같은 주문 5,000건을 무게를 보지 않는 판정으로 계산하면 주문 689건(13.8%)에서 20kg을 넘는 박스가 나왔고, 가장 무거운 박스는 45.7kg이었습니다.
- 무게와 접수 한도를 함께 판정하면 한도를 넘는 박스가 0개였습니다. 대신 박스 수가 5,551개에서 6,036개로 8.7% 늘었습니다.

**테스트 결과**

| 주문 수 | 총 시간 | 주문당 평균 | p50 | p95 | 최대 |
| :-: | :-: | :-: | :-: | :-: | :-: |
| 100건 | 0.36초 | 3.6ms | 1.8ms | 12.8ms | 16.9ms |
| 1,000건 | 4.0초 | 4.0ms | 2.4ms | 12.9ms | 31.2ms |
| 5,000건 | 21.0초 | 4.2ms | 2.3ms | 13.8ms | 96.6ms |

| 판정 방식 (주문 5,000건) | 박스 수 | 20kg 넘는 박스가 나온 주문 | 가장 무거운 박스 |
| :-: | :-: | :-: | :-: |
| 치수만 판정 | 5,551개 | 689건 (13.8%) | 45.7kg |
| **치수·무게 판정** | **6,036개** | **0건** | **20kg 이하** |

- 주문 수가 늘어도 주문당 계산 시간은 유지됐습니다.
- 추천한 박스 6,036개가 모두 택배 접수 한도를 지켰습니다.
