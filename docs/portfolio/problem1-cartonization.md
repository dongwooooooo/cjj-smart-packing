## 문제 1. 박스 추천 — 실제로 담기고 택배로 보낼 수 있는 박스

### 문제 배경

- **들어가지 않는 박스 추천**: 부피 합으로 비교하면 들어가지 않는 박스를 추천합니다. 유효 내치수 30×30×30 박스에 25×25×20 상품 두 개는 부피로는 통과하지만, 어떤 방향으로도 함께 들어가지 않습니다.
- **택배로 보낼 수 없는 박스**: 무게를 보지 않고 박스 개수만 줄이면, 다품목 주문 5,000건(주문당 1~10품목, 평균 16.5개) 중 689건(13.8%)에서 택배 접수 한도 20kg을 넘는 박스가 나왔습니다. 가장 무거운 박스는 45.7kg이었습니다.

### 해결 과정

**박스 판정**

| 해결 방안 | 장점 | 단점 및 기각 사유 |
| :-: | :-: | :-: |
| 1. 부피 합산 비교 | • 구현 단순 | • 들어가지 않는 박스를 추천해 현장에서 재포장 |
| 2. 상품별 6방향 회전 검사 | • 낱개 통과 여부는 정확 | • 여러 상품을 함께 담을 수 있는지 판정하지 못함 |
| **3. 실제 배치를 만들어 판정 (최종 채택)** | **• 판정 결과가 곧 배치라 들어가지 않는 추천이 없음** | **• 휴리스틱이라 실제로는 담기는 조합을 놓칠 수 있음** |

**무게 반영**

| 해결 방안 | 장점 | 단점 및 기각 사유 |
| :-: | :-: | :-: |
| 1. 박스 무게 한도 20kg만 추가 | • 변경 최소 | • 무게 때문에 택배 요금이 한 구간 오르는 편성을 구분하지 못함 |
| 2. 박스 크기별 요금 구간의 무게 상한을 한도로 | • 무게가 분할에 반영됨 | • 요금 구간을 물리 한도로 오해한 모델. 그대로 보낼 수 있는 박스까지 나눔 |
| **3. 편성 기준을 총 택배 요금으로 (최종 채택)** | **• 나눠 담을지, 한 박스에 담고 요금 구간을 올릴지를 계산이 판정** | **• 편성 탐색 범위가 넓어짐** |

**핵심 설계 결정**

- **배치 판정**: 이미 놓인 상품의 모서리가 만드는 후보 지점마다 상품을 6방향으로 놓아 보며 실제 배치를 만듭니다. 박스 각 변에서 마진 3cm를 빼고, 파손주의 상품은 완충재 두께만큼 키워서 놓습니다.
- **편성 기준**: 총 택배 요금이 가장 적은 편성을 고르고, 같으면 박스 수, 그다음 총 부피가 적은 쪽을 고릅니다. 박스 요금은 세 변의 합 구간과 무게 구간 중 높은 쪽으로 계산합니다.
- **나눠 담는 후보까지 탐색**: 주문 전체를 박스 하나에 담는 후보와, 부피 큰 순으로 담은 뒤 상품을 옮겨 가며 개선한 후보를 비교합니다. 상품을 새 박스로 옮기는 경우도 봐야 무거운 박스를 나누는 편성에 닿습니다.
- **접수와 출고의 무게 검사**: 상품 하나가 20kg을 넘으면 주문 접수에서 거부합니다. 포장 완료 때는 저울에 잰 무게를 예상 무게와 대조해, 허용 오차를 넘으면 완료를 막습니다.

### 결론

| 항목 (다품목 주문 5,000건) | 개선 전 | 개선 후 |
| :-: | :-: | :-: |
| 20kg 초과 박스 | 691개 (주문 13.8%) | **0개** |
| 가장 무거운 박스 | 45.7kg | **20kg 이하** |
| 박스 수 | 5,551개 | 6,036개 |

- **박스 수 증가**: 20kg을 넘던 박스를 편성 단계에서 나누면서 박스가 8.7% 늘었습니다.
- **편성 시간**: 5,000건을 편성하는 데 21초, 주문당 p95 13.8ms가 걸렸습니다(단일 스레드).

## 작성 메모 (Docs 에 옮기지 않음)

- 근거: `docs/evidence/benchmark/weight-objective-comparison.md`(개선 전·후 비교, backend `test/weight-objective-comparison` b0f5ac1), `docs/evidence/benchmark/bench2.log`(편성 시간), `backend/docs/decisions-weight.md`.
- "개선 전"은 617fc5f 편성(박스 개수 → 부피, 치수만 봄)이다. 편성 방식 자체(3D 배치 판정)는 전·후 같고, 다른 것은 편성 기준과 무게 반영이다.
- 주문·상품은 합성 데이터다. 시연 CJ 식품 11종 치수 ±20%, 무게 = 원 상품 밀도 × 부피. 1~3품목 주문에서는 개선 전에도 20kg 을 넘지 않았다(최대 15.7kg).
- 운임은 결론에 넣지 않았다. 전·후 운임 차이(−1.7%)는 무게가 아니라 탐색 범위 확장에서 나왔고, 요금표도 파스토 2024 인용이라 CJ 공식 요금과 대조하지 못했다.
- 편성 시간은 개발 PC(Apple M2 Pro) 측정이다.
- 이전 판(3D 배치 알고리즘 상세, 계약 대조, 테스트 수, NPE 결함)은 git 이력 962e49d 이전 커밋에 있다.
