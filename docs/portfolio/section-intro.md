## 요구사항과 범위 결정

풀필먼트 공정 중 입고와 출고 두 지점만 다뤘습니다. 입고 작업자는 신상품을 카메라 아래 올려 촬영하고, 화면에 표시된 치수를 확정한 뒤 수량을 입고합니다. 포장 작업자는 토트를 스캔해 배송 단위의 주문 내역과 추천 박스를 확인하고 포장을 완료합니다.

### 기능 요구사항

  - 촬영 사진 3장에서 가로·세로·높이(cm)를 추론하고, 작업자가 확정한 값만 상품 마스터에 저장합니다.
  - 출고지시를 배치로 받아 배송 단위 편성, 박스 추천, 라인 배정, 토트 할당을 한 트랜잭션으로 처리합니다.
  - 재고 차감은 포장 완료 시점 한 곳에서만 실행됩니다. 포장 완료 시 실측 무게를 받아 예상 무게와 대조합니다.

### 비기능 요구사항

  - 추론은 동기 응답이며 촬영 응답 p95 1초를 SLO로 둡니다. 초기 계약 8초는 GPU 서빙 전제였고, CPU 서빙으로 전환한 뒤 문제 2에서 재설정했습니다. 타임아웃(실패 판정)은 별도 값입니다.
  - 추론 모델 서버가 준비되기 전에도 입고 흐름 전체가 동작해야 합니다(미설정 시 mock 응답).
  - 배치 편성은 같은 입력에 대해 항상 같은 결과를 산출합니다(결정성).

### 범위에서 뺀 것과 이유

MVP 문서 초안에 있던 기능 중 세 가지를 개발 중에 제거했습니다. 결정 이력(D-01~D-25)에 제거 이유를 기록해 같은 논의가 반복되지 않게 했습니다.

| 제거한 기능 | 결정 | 이유 |
| :-: | :-: | :-: |
| 재피킹 백엔드(테이블·API 2개·상태·에러 코드) | D-06, 08.20 | 피킹이 시연 범위 밖. 수량 불일치는 화면 표시로만 처리. 실물 토트를 라인으로 되돌리면 주문시간순 우선순위로 먼저 처리되므로 별도 상태 관리가 필요하지 않음(D-20) |
| 출고 포장 화면의 재고 현황 영역 | D-19, 08.21 | 제품 재고 조회 API가 계약에 없어 화면 때문에 계약을 새로 만들어야 함. 박스 재고는 추천 응답에 이미 포함돼 중복 |
| 미등록 바코드 수기 등록 경로(API 2개) | D-21, 08.22 | 표준 마스터(코리안넷)에 없는 상품은 입고 대상이 아님. 작업자가 분류를 직접 선택하면 표준 분류 체계가 오염됨 |

처음부터 범위 밖으로 둔 것은 피킹·창고 적재·창고 사용률 예측, 3D 형상 재구성, 무게 자동 추정(저울 연동값 사용), 실시간 창고 시스템 연동입니다.

**Vision AI 모델 성능.** 학습 데이터는 AI-Hub "물류공간 예측 데이터"(512px 리사이즈본)이며 학습·검증 물품은 7,676 / 958개로 겹치지 않습니다. 손실은 Huber에 비대칭 가중을 더한 형태로, 가로·세로 축에서 실제보다 작게 예측하는 오차에 1.6배 벌점을 줍니다. 작게 예측하면 들어가지 않는 박스를 추천하고, 크게 예측하면 박스가 한 단계 커지는 데 그치기 때문입니다. 검증셋 2,024품목을 서빙 코드로 평가한 축별 MAE는 length 2.06 / width 2.17 / height 1.62cm(이하 같은 순서)이고, 과정 시작 시 베이스라인은 2.69 / 3.74 / 4.99cm였습니다. 학습 당시 검증에서는 학습 배경 1.31 / 1.41 / 1.17cm, 학습에 쓰지 않은 배경 1.57 / 1.69 / 1.77cm로 배경이 바뀌어도 악화가 0.3~0.6cm에 그쳤습니다. 배경 합성 증강을 적용하고 매 실험마다 미학습 배경으로 검증한 결과입니다. 두 평가의 절대값 차이는 분할·촬영 슬롯 고정 여부가 달라서 생겼습니다. 문제 3은 이 불일치를 다룹니다. 모델은 신뢰도를 출력하지 않으며(표본 958개로는 구간별 확률표가 불안정), 촬영 구도가 학습 데이터와 다르면 성능을 보장할 수 없습니다.

**서빙.** torch 가중치를 빌드 시 ONNX로 변환해 같은 사진 3장 기준 추론 1,070ms를 185ms로, 모델 로드 3.10초를 0.22초로 줄였습니다(로컬 CPU 실측 2026-08-25, 예측값은 소수 1자리까지 동일). Hugging Face 토큰은 BuildKit secret mount로만 전달해 이미지 레이어에 남지 않습니다.
